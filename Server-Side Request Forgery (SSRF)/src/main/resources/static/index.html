Mecanismo de explotación

El servidor procesa una URL no autenticada ni validada. Al realizar la petición saliente desde la red de confianza, hereda los privilegios del host y elude firewalls perimetrales.

Cliente → Backend → Intranet / Metadata

Mecanismo de mitigación

Lista blanca de esquemas (HTTP/S), resolución previa de DNS con validación de IP (bloqueo de loopback, RFC 1918 e IMDS 169.254.169.254) y deshabilitación de redirecciones 302.

Cliente → Validador DNS/IP → 400 Bad Request

Referencia de controles y mitigación

Confianza perimetral

El servidor se encuentra dentro de la zona de confianza de la red. Una petición SSRF utiliza el proceso backend como intermediario para evadir filtros perimetrales y consultar puertos no expuestos.

Metadatos Cloud (IMDS)

En entornos AWS, GCP o Azure, la dirección de link-local 169.254.169.254 expone credenciales de rol de la máquina. El acceso mediante SSRF compromete tokens de infraestructura.

Esquemas no HTTP

Bibliotecas estándar permiten protocolos como file:// o gopher://. Esto habilita lectura directa del sistema de archivos local si no existe whitelist explícita de esquema.

Implementación de defensa

SsrfValidatorService valida protocolo estricto, realiza resolución DNS y rechaza direcciones de loopback (127.0.0.1, ::1), RFC 1918 y rangos de metadatos antes del handshake de red.
